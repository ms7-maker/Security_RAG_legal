# ⚖️ Security_RAG_legal — карта доступа юрфирмы

**Интерактивная схема** — кто в юридической фирме к каким документам имеет доступ в умном ассистенте **Legal RAG Assist**.

> ⚠️ Это **план и визуализация**, а не готовая программа. Показывает, *как должна работать* система ролей и защит.

### 🗺️ Как открыть карту

Репозиторий **private**: на бесплатном GitHub **нет публичной ссылки** на сайт (GitHub Pages для private недоступен). Карту нужно открыть **на своём компьютере**.

1. Скачайте проект: [Download ZIP](https://github.com/ms7-maker/Security_RAG_legal/archive/refs/heads/main.zip) *(нужно быть залогиненным в GitHub)*.
2. Распакуйте архив.
3. Дважды кликните файл **`index.html`** — карта откроется в браузере (Chrome, Edge и т.д.).

Или из папки проекта в Cursor: правый клик по `index.html` → **Reveal in File Explorer** → открыть двойным кликом.

📄 Код карты на GitHub (это **исходник**, не живая страница): [index.html](https://github.com/ms7-maker/Security_RAG_legal/blob/main/index.html)

## 🤔 Зачем это нужно

В юрфирме документы разной секретности:

- 📚 общие регламенты и FAQ;
- 📂 базы знаний по отраслям права;
- 📜 договоры (черновики и подписанные);
- 👥 сотрудники, клиенты, карточки дел.

Ассистент должен отвечать на вопросы **только в рамках роли**: трудовой юрист не видит налоговую практику, а архив договоров — только у отдела договоров (по номеру дела).

## 👥 Роли

| Роль | Что видит |
|------|-----------|
| 🏛️ **Консультант (административное право)** | Общие материалы + своя практика |
| 👷 **Консультант (трудовое право)** | Общие материалы + своя практика |
| 🏢 **Консультант (корпоративное право)** | Общие материалы + своя практика |
| 🧾 **Консультант (налоговое право)** | Общие материалы + своя практика |
| 📋 **Отдел договоров** | Общие материалы + договоры **по ID дела** |
| 🛡️ **Партнёр** | Всё на просмотр; правка общих материалов и справочников |

**Обозначения:** 👁️ просмотр · ✏️ редактирование

## 📂 Базы документов

### БД_1 · Общие материалы
Регламенты фирмы, этика, шаблоны писем, FAQ для клиентов.  
Доступ: все роли (просмотр); партнёр — ещё и правка.

### БД_2 · Практики по отраслям

| Практика | Примеры документов | Кто |
|----------|-------------------|-----|
| Административное | жалобы в госорганы, КоАП, шаблоны возражений | консультант (адм.) + партнёр |
| Трудовое | шаблоны ТД, споры по увольнению, ЛНА, ТК РФ | консультант (труд.) + партнёр |
| Корпоративное | уставы, протоколы собраний, обзоры M&A | консультант (корп.) + партнёр |
| Налоговое | консультации, ответы ФНС, споры по доначислениям | консультант (налог.) + партнёр |

Чужая практика в симуляции **гасится**.

### БД_3 · Отдел договоров (изолированный контур)

Контракт после подготовки уходит **сюда**, а не остаётся в практике консультанта.

| Подраздел | Кто | Особенности |
|-----------|-----|-------------|
| Черновики | отдел договоров 👁️✏️, партнёр 👁️ | доступ по ID дела, MFA |
| Подписанные | отдел договоров 👁️ (ID), партнёр 👁️ | маскирование PII, доступ по ID |

### БД_4 · Внутренние справочники
Сотрудники, клиенты, карточки дел — **только партнёр** (с журналом изменений).

## 🔐 Защиты

| Маркер | Смысл |
|--------|--------|
| 🔒 **Маскирование PII** | ФИО, ИНН, счета → `[Client]`, `[INN]`, `[Account]` |
| 🔑 **Доступ по ID** | Нельзя выгрузить «все договоры» |
| 🔑 **MFA** | Доп. подтверждение для БД_3 и БД_4 |
| 📝 **Журнал** | Правки справочников пишутся навсегда |

## 🖱️ Как пользоваться картой

1. Откройте `index.html` в браузере.

## 💡 Экономический эффект

- ⏱️ Юрист не ищет «чужие» папки — ассистент сразу в своей практике.
- 💰 Меньше риска утечки клиентских договоров (изолированный отдел + ID).
- 🛡️ Маскирование реквизитов снижает риск штрафов и репутационных потерь.
- 📋 Партнёр контролирует качество без выдачи всем полного архива.

### 📣 Один абзац для клиента

> **Security_RAG_legal** — карта доступа умного ассистента для юридической фирмы. Консультанты работают только со своей отраслью права; договоры живут в отдельном контуре отдела договоров по номеру дела; партнёр видит всё для контроля. Это экономит время поиска, снижает риск утечек и задаёт понятные правила до разработки системы.
